## 3. 問題の品質方針（最重要）

テキストを取り込めないため、誤った知識を覚えさせる事故が最大のリスク。
以下を厳守する。

1. **分野ごとに公開一次資料を実際に読んでから作問する。**
   記憶だけで数値（含有率・年代・温度・時間・品種名など）を書かない。
   主に使う資料: 農林水産省、農研機構、日本茶業中央会、日本茶インストラクター協会、
   各県茶業研究所、日本茶業学会。
   **1分野につき最低2〜3本の資料に実際にアクセスしてから作問すること。**
   資料を読まずに作問した場合は、それは `verified: false` である。

2. **裏が取れた問題** … `verified: true` ＋ `source`（資料名・URL・確認日）を必ず付ける。

3. **裏が取れなかった問題** … `verified: false` で出題し、画面に
   **「※テキストで要確認」バッジ**を表示する。受験者が手元のテキストで照合できるようにする。
   （除外しない。除外すると試験範囲に穴ができるため）

4. 推測で書いた内容を断定形で解説しない。

### 受験者の要点メモ（写真）の扱い
- 受験者**本人が書いたメモ**の写真のみ受け取る。テキストのページを撮影したものは受け取らない。
- メモは「どの論点が重要か」の手がかりとして使い、事実そのものは公開資料で裏を取る。

## 4. アプリの構成

### 4.1 方針
`pharmacy quiz`（既存の完成済みアプリ）を丸ごとコピーし、日本茶用に作り替える。
ユーザーの選択により案Bを採用。

### 4.2 コード調査で判明した重要事項
- **五肢択一はコード変更不要**。`question.choices` の要素数だけボタンを生成する作りのため、
  4択でも5択でも動作する（`js/app.js` renderQuestion / `js/quiz-engine.js` shuffleChoices）。
- **選択肢は表示のたびにシャッフルされる**。正解の位置を記憶して答えるのを防げる。本番対策上そのまま活かす。
- **「間違えた問題だけ復習」は実装済み**（弱点復習モード / `getWeakPointQuestions`）。新規実装不要。
- **模試モード（時間制限）は未実装**。新規に作る。
- 既存は `verified: false` の問題を出題プールから除外する。本件では方針が逆なので変更する。

### 4.3 コピーするもの / 捨てるもの

**コピーする**
- `index.html`, `css/style.css`
- `js/app.js`, `js/quiz-engine.js`, `js/storage.js`, `js/stats.js`, `js/validate-questions.js`
- `manifest.json`, `service-worker.js`, `icons/`, `dev-server.js`, `package.json`, `.nojekyll`, `.gitignore`

- `tools/` のPMDA・法令関連 23本

### 4.4 消す機能
| 機能 | 理由 | やり方 |
|---|---|---|
| 利用者の切り替え（profile画面） | 利用者は受験者1人 | **画面（UI）だけ削除し、storage.js の利用者ごとの保存構造は1人固定のまま温存**。保存構造を書き換えると成績消失の事故リスクがあるため |
| 先生への成績共有 / 先生用集計画面 | 用途なし | 画面・JS・テストとも削除 |
| 疑義照会の2段階出題（`type: 'query'`） | 日本茶に該当形式なし | `renderQueryStep1/2`, `onQueryStep1/2` を削除 |
| 難易度（初級・中級・上級） | 本番に難易度区分がなく、2日で400問作るのに3分割する余裕がない | `difficulty-screen` と `DIFFICULTIES` を削除。データからも `difficulty` を廃止 |

### 4.5 残す機能
ホーム（10分野選択）／クイズ／結果（円グラフ・ふりかえり）／分野別正答率／ブックマーク／
弱点復習モード／連続学習日数／PWA（ホーム画面設置・オフライン動作）

### 4.6 足す機能

**A. 模試モード**
- 全分野からランダムに **50問 / 制限時間75分**
- 途中で正誤・解説を表示しない（本番同様、最後にまとめて採点）
- 残り時間を常時表示。時間切れで自動採点
- 終了後: 総合正答率＋分野別正答率、間違えた問題は自動で弱点リストへ
- 根拠: 本番の出題数は非公開。仮に100問150分なら1問90秒で、50問75分と同じペース配分になる

**B. 「※テキストで要確認」バッジ**
- `verified: false` の問題も出題する（既存の除外挙動を変更）
- 問題文の上にバッジを表示し、解説欄にも注意書きを出す

### 4.7 通常セッションの問題数
既存の `QUESTIONS_PER_SESSION = 10` をそのまま使う（隙間時間に1セット解ける長さ）。

## 5. 問題データの形

`data/questions.json`

```json
{
  "id": "chemistry-001",
  "category": "chemistry",
  "question": "問題文",
  "choices": ["選択肢1", "選択肢2", "選択肢3", "選択肢4", "選択肢5"],
  "correctIndex": 0,
  "explanation": "なぜそれが正解か。他の選択肢がなぜ誤りかも簡潔に添える",
  "source": {
    "name": "資料名・該当箇所",
    "url": "https://...",
    "confirmedDate": "2026-09-13"
  },
  "verified": true
}
```

- `choices` は**必ず5つ**
- `difficulty` フィールドは使わない
- `verified: false` のとき `source` は省略可
- `id` は `<分野ID>-<3桁連番>`

`data/categories.json` は上表の10分野（id と name）。

## 6. 自動チェック（間違いを防ぐ仕組み）

`js/validate-questions.js` を日本茶用に作り替え、以下を検査する。

1. `choices` がちょうど5要素であること
2. `correctIndex` が 0〜4 の範囲内であること
3. `id` が全体で重複していないこと
4. `category` が定義済み10分野のいずれかであること
5. 同一問題内で選択肢のテキストが重複していないこと
6. `verified: true` なら `source.url` と `source.confirmedDate` が存在すること
7. `question` と `explanation` が空でないこと

既存テスト（quiz-engine / stats / storage）はそのまま流用。
模試モードは新規のためテストを書く（残り時間の計算、時間切れ時の自動採点、
途中で解説が出ないこと）。
